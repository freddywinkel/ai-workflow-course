# Course 1 Validation Tools

## Validate the current package

[`validate_package.py`](validate_package.py) treats
[`curriculum.json`](../curriculum.json) as the current-course source of truth.
It checks:

- Course 1 program, course, career, group, and document metadata;
- normalized configured lesson paths, stable current and legacy IDs, unique
  paths, and ISO revision dates;
- exactly 9 ordered foundation and 9 ordered module progress lessons;
- the shared heading contract in all 9 modules;
- syntax of current JSON files;
- all current Course 1 JSON Schema contracts in
  [`schemas/`](../schemas/);
- the synthetic practice-data headers, 15 work items, 13 expected issues,
  unique identifiers and comparison keys, R001–R011 coverage, fixed assessment
  date, and explicit no-real-data guarantees;
- a standard-library reproduction of the frozen expected issues;
- current local Markdown links.

Run from the course root:

```powershell
python tools\validate_package.py
```

The script always writes
[`VALIDATION_REPORT.md`](../VALIDATION_REPORT.md). A structural failure produces
exit code 1. An invalid root or report-write failure produces exit code 2.

You can validate another copy or write a temporary report:

```powershell
python tools\validate_package.py --root C:\path\to\course
python tools\validate_package.py --report C:\path\to\report.md
```

Paths containing spaces should be quoted.

## Optional deeper parsing

The validator itself uses only the Python standard library. If `jsonschema` and
PyYAML are installed, it also performs Draft 2020-12 schema
meta-validation and parses `stack-manifest.yaml`.

```powershell
python -m pip install -r tools\requirements-validation.txt
python tools\validate_package.py
```

If those packages are absent, the report contains explicit warnings. Their
absence does not hide or disable the standard-library contract, curriculum,
practice-data, or link checks.

## Validation scope

The validator covers the **current Course 1 package**. It deliberately ignores:

- `future_courses/`, which contains archived source material and proposed later
  courses;
- `app/dist/`, which is generated by the PWA build;
- `node_modules/` and other dependency or cache directories;
- Git metadata.

Current Markdown source elsewhere in the package remains in scope. A moved or
deleted current lesson therefore cannot disappear merely because an old copy
still exists in `future_courses/`.

## Practice-data control

The fixed learner fixtures are:

- [`practice_data/work_items.csv`](../practice_data/work_items.csv);
- [`practice_data/expected_issues.csv`](../practice_data/expected_issues.csv);
- [`practice_data/README.md`](../practice_data/README.md), which owns the
  R001–R011 definitions and the fixed assessment date.

Do not edit the answer key to make an implementation or validator pass. Change
the fixtures only as an intentional course revision, update their requirements
and expected results together, increment affected curriculum revisions, and
review the resulting validation report.

## What a PASS does not prove

A PASS proves deterministic package structure. It does not verify:

- whether external sources remain current;
- legal, privacy, security, or sector-specific compliance;
- live AI-provider behaviour;
- PWA rendering, accessibility, or offline behaviour;
- the quality of a learner's capstone;
- production readiness.

Use the source audit, PWA test and visual-review workflow, and the course
evaluation, UAT, and handover gates for those questions.
