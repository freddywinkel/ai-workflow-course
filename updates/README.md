# Evergreen Update Reports

This folder is for course maintainers. Learners do not run
[`../EVERGREEN_UPDATE_PROMPT.md`](../EVERGREEN_UPDATE_PROMPT.md) as a setup
step. The prompt is a delta workflow and does not authorize its own edits or a
new release. Maintainers choose read-only diagnosis or a separately approved
repair mode before changing a later-course live artificial intelligence (AI)
provider lab, before publishing later-course client-pilot guidance, after a
material source change, and at least every 12 weeks while the material is
actively maintained. Full/final audits use
[`../COURSE_1_GROUND_UP_AUDIT_PROTOCOL.md`](../COURSE_1_GROUND_UP_AUDIT_PROTOCOL.md).

For each audit, first save the unchanged report here as:

```text
YYYY-MM-DD_CHANGE_REPORT.md
```

Only after that report exists should a revised course copy be created. Keep the
old issued copy and changelog entry. A revision record should identify:

- the original and replacement statements;
- legal or product status and effective date;
- affected foundations, modules, labs, manifests, and tests;
- primary official sources and verification date;
- migration work and test reruns;
- unresolved risks and next review date.

If live browsing of both official vendor documentation and primary legal or
authority sources is unavailable, the audit must stop with `UNVERIFIED`; do not
create a reassuring partial update.
