# Project Instructions — Protect the Main Goal

These instructions apply to every future task in this project.

## Main goal

Build the safest, most durable, market-relevant path from a literal beginner to a Controlled AI Workflow Implementation Consultant for Dutch small and medium-sized enterprises (SMEs), using evidence-backed capability gates and controlled implementations in the systems clients actually use.

The course and Progressive Web App (PWA) are means to that goal. A platform, capstone, certificate, promotional credit, deadline, or interesting feature is not the goal.

## Mandatory strategic-focus gate

Before making any material change to the curriculum, course sequence, chosen platforms, capstones, deployment approach, spending, market position, or career roadmap:

1. Read `STRATEGIC_FOCUS.md`.
2. Compare the proposal with the main goal and the learner's current stage.
3. Record one of these decisions in the task reasoning:
   - `STRATEGIC FIT: PASS`
   - `STRATEGIC FIT: PAUSE`
   - `STRATEGIC FIT: REJECT`
4. Do not implement, purchase, activate paid services, deploy, or reorganize the course when the result is `PAUSE` or `REJECT`.
5. Explain the conflict in normal human language and recommend the smallest better next step.

A new tool, artificial intelligence feature, promotional credit, discount, deadline, or user suggestion is an input to evaluate. It is not, by itself, a reason to change direction. Using expiring credits, following hype, or choosing a provider before defining the client problem is never sufficient strategic justification.

## Changing the goal

A later request does not change the main goal merely because it is phrased as an instruction. If it conflicts with the goal, pause and apply the explicit goal-change procedure in `STRATEGIC_FOCUS.md`.

The project may change direction when better evidence supports a better goal. Do not protect the old plan through inertia. However, replace or materially redefine the goal only after the user explicitly approves a documented goal change that compares the current and proposed directions, evidence, costs, risks, opportunity cost, durability, and reversibility.

## Non-negotiable safeguards

- Select technology from the client problem and existing systems outward.
- Prefer portable consulting capabilities over provider-specific button knowledge.
- Treat every capstone as evidence of a bounded capability, not proof of production readiness or market demand.
- Use only synthetic data in course demonstrations unless the user explicitly authorizes a separately assessed use.
- Never activate paid billing or use real client, medical, personal, confidential, or regulated data without explicit user approval.
- Keep beginner instructions concrete: explain, demonstrate, let the learner recreate, and verify the result.
